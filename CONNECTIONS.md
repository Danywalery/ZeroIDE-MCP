# Постоянное подключение к MCP

## Выбор способа

| Режим | Что нужно | Адрес |
|---|---|---|
| ngrok | Бесплатный аккаунт ngrok, установленный ngrok.exe, authtoken аккаунта | Постоянный домен, назначенный аккаунту; свой домен не нужен |
| Cloudflare | Свой домен в Cloudflare, именованный туннель и cloudflared | Постоянный hostname пользователя |
| SSH / VPS | Уже настроенный VPS и SSH-ключ | Адрес своего сервера |
| Локально | Ничего | Только 127.0.0.1, не для облачного подключения Notion |

Никакого общего шлюза проекта: аккаунты, домены и токены принадлежат пользователю. Бесплатность зависит от действующих лимитов провайдера; это не обещание безлимита. Tailscale, LAN и Quick Tunnel не добавлены в этой доработке.

## Поведение приложения

- Открытие программы показывает tray, но не включает сервер и туннель.
- «Включить MCP» запускает node и выбранный туннель. «Выключить MCP», таймер, остановка по неактивности и выход из tray останавливают оба процесса.
- При падении туннеля supervisor повторяет запуск с задержкой, только пока MCP включён.
- Смена активного способа при включённом MCP требует подтверждения: текущая удалённая сессия оборвётся.
- Настройки → Подключение: выбранный способ, независимые состояния сервера и сети, сохранённая ссылка, «Копировать», «Обновить», «Настройки / адрес», «Перезапуск туннеля».
- «Обновить» читает адрес из локального API ngrok и делает разовую проверку `/health`. В выключенном состоянии ничего не запускает. Cloudflare использует сохранённый hostname.
- Проверка из самого ПК не доказывает доступность из инфраструктуры Notion: окончательная проверка — подключение MCP из клиента. Запущенный процесс не равен рабочему публичному адресу.
- Постоянные внешние health-запросы не отправляются; периодически опрашивается только локальный API ngrok.

## ngrok: установка с агентом

1. Агент скачивает официальный ngrok для Windows, проверяет подпись издателя и устанавливает его в `%LOCALAPPDATA%\ZeroIDE-MCP\tools\ngrok\ngrok.exe`. Не брать сторонние бинарники.
2. Пользователь входит в свой аккаунт через браузер: https://dashboard.ngrok.com/ (можно Google). Агент не запрашивает пароль Google.
3. Пользователь копирует **authtoken ngrok** из аккаунта и вводит его в маскированное поле «Новый authtoken аккаунта ngrok» в настройках подключения. Не в чат, не в терминал агента.
4. Конфиг по умолчанию — `%LOCALAPPDATA%\ZeroIDE-MCP\tools\ngrok\ngrok.yml`, `web_addr: 127.0.0.1:4041`. В tray-config.json записываются только пути и адрес. Файл секрета доступен владельцу и SYSTEM. Пустое поле токена оставляет существующий конфиг; новый токен с подтверждением заменяет его содержимое.
5. Выбери ngrok и включи MCP. Нажми «Обновить», скопируй HTTPS-ссылку с `/mcp` и добавь её в Notion.
6. В Notion используй **OAuth** или **Bearer-токен MCP**, а не authtoken ngrok. Оба адреса одного сервера используют одну систему прав/токенов MCP; отдельный токен «для ngrok-пути» не нужен.
7. **Если окно OAuth показывает предупреждение ngrok — нажми “Visit Site”.** Это предупреждение бесплатного ngrok, а не ошибка MCP. Если окно закрыто по таймауту, повтори подключение и сразу нажми кнопку.

### Сохранение и смена адреса

Назначенный аккаунту домен сохраняется между перезапусками. «Обновить» синхронизирует фактический HTTPS-адрес агента, а не выпускает новый домен. Чтобы сменить адрес, сначала проверь доступные домены в аккаунте ngrok, затем вставь доступный этому аккаунту HTTPS-адрес в «Настройки / адрес». Приложение запускает ngrok с `--url` для сохранённого домена. Произвольный недоступный домен работать не будет. При смене адреса вручную обнови URL подключения и в Notion.

Конфиг можно выбрать свой; его локальный API должен слушать `127.0.0.1:4041` (либо порт `NgrokApiPort` в tray-config.json). Не отключай Bearer/OAuth ради доступности.

## Cloudflare: именованный туннель

1. Установи официальный cloudflared. Режим `--token-file` требует **2025.4.0+**.
2. В аккаунте Cloudflare создай именованный туннель и публичный hostname на своём домене. Направь его на `http://127.0.0.1:39011` (или текущий Port приложения).
3. В настройках Cloudflare укажи `cloudflared.exe`, публичный HTTPS-hostname и токен именно этого туннеля. Он хранится локально в защищённом `tools\cloudflare\tunnel.token`, не передаётся аргументом процесса.
4. Альтернатива: путь к локальному конфигу и ID/имя именованного туннеля. Этот вариант приоритетнее token-file; конфиг должен содержать правильные credentials и ingress. Настройка домена/DNS остаётся в аккаунте Cloudflare, приложение не придумывает hostname.
5. Включи MCP, проверь адрес и подключись из Notion. Журнал агента туннеля — `tools\cloudflare\agent.log`.

На ПК владельца проекта Cloudflare пока не проходит сетевую проверку. Реализация запуска и конфигурации не означает подтверждённую работу этого провайдера на данном ПК. Не заменять именованный туннель случайной Quick Tunnel ссылкой.

## Для разработчиков

Новые поля `TrayConfig`: `ConnectionMode` (`local|ngrok|cloudflare|ssh`), `NgrokUrl`, `NgrokExePath`, `NgrokConfigPath`, `NgrokApiPort`, `CloudflareUrl`, `CloudflareExePath`, `CloudflareConfigPath`, `CloudflareTunnelId`, `CloudflareTokenFile`, `SshPublicUrl`. Старое `TunnelEnabled=false` означает локальный режим; старый конфиг без ConnectionMode сохраняет SSH. Обновление бинарника не должно молча менять активный профиль.

Секреты не писать в журнал/команды/чат. Не печатать config.env или ngrok.yml для диагностики. Публичный `/health` минимален, `/local/*` снаружи должен отвечать 403. Проверка MCP — initialize/list tools с действующей авторизацией; не выполнять пользовательские команды в ходе проверки.

Официальные источники: https://ngrok.com/docs/pricing-limits/free-plan-limits и https://developers.cloudflare.com/tunnel/reference/run-parameters/ .
